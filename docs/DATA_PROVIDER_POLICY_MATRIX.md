# Data Provider Policy Matrix

What each data source and service may be used for in this product, and how the code enforces it. Reviewed 2026-10-22 from the providers' public pages listed under each entry. **This is an engineering reading, not legal advice.** Terms change; re-check before enabling a provider for a new purpose and have counsel confirm anything marked *verify*.

Every discovery source declares its policy in code. Interactive Google Places uses `getRetentionRules`/`getAttributionRequirements`; autonomous sources use the richer `DiscoverySourceDeclaration` in `src/lib/domain/discovery-sources.ts` (permitted uses, retention, attribution, licence evidence, access, cost, limits). The UI shows the declaration, and only fields the source permits can be written to the CRM. Restrictions may not be worked around by copying results through AI, screenshots, browser automation or another provider. The full audit and activation checklist are in [AUTONOMOUS_DISCOVERY](AUTONOMOUS_DISCOVERY.md).

## Sources and notes

**Google Places API (New)** — [Places API policies](https://developers.google.com/maps/documentation/places/web-service/policies): Place IDs are exempt from caching restrictions and "you can store place ID values indefinitely"; other Places content must not be pre-fetched, cached or stored beyond the allowed exceptions; attribution is required when displaying Places data without a Google Map. Pricing depends on the fields requested (the configured field mask includes `websiteUri`, which bills at a higher SKU than names and addresses — check the current [pricing page](https://developers.google.com/maps/billing-and-pricing/pricing)). Absence of `websiteUri` is not evidence that no website exists.

**Brave Search API** — [Terms of Service](https://api-dashboard.search.brave.com/documentation/resources/terms-of-service), last updated 1 September 2026. Section 3(b)(i) prohibits storing, caching or creating a database of Search Results "other than transient storage"; 3(b)(xii) prohibits redistribution or resale; 3(b)(xiii) prohibits using results to create, train, fine-tune or benchmark AI models; 3(a)(ii) permits use with your applications; 4(c) requires end users to be bound by a written agreement with you (our Terms of use for team members must cover this before enabling the key); 13(c) requires deletion on termination. Brave's help pages describe separate "Data for AI" and "storage rights" plans (*verify* which plan the account holds before sending results to a model).

*Design consequence (implemented in Phase 3):* the Website Verification agent keeps Brave results in memory for the duration of the run. The verification record (`website_verifications.evidence`) stores the queries it sent with their purpose, result counts and time, aggregate counts (results naming the business, social platforms seen), the sites it then **independently** checked with its own verdicts, and its conclusion — not titles, snippets or result lists. Usage records hold the job ID and query purpose only. Whether retaining the independently checked candidate sites is acceptable under 3(b)(i) is a judgement call — *verify* with Brave or counsel before enabling the key in production.

Automated search additionally needs an explicit Brave Search budget (COST_CONTROL); the route used by the manual *Search* button needs the key and the daily quota. CI and the E2E suite use a labelled simulated provider (`SIMULATE_EXTERNAL_TOOLS=true`, ignored whenever Supabase is configured).

**WhatsApp** — [WhatsApp Business Messaging Policy](https://whatsappbusiness.com/policy/): "You may only contact people on WhatsApp if: (a) they have given you their mobile phone number or username" and you have received opt-in permission confirming they wish to receive messages; opt-out requests made on or off WhatsApp must be respected; outside the 24-hour customer service window, only approved Message Templates may be sent, and conversations may only be initiated with an approved template. Enforcement covers "messaging people at scale in an unauthorized manner". A number published on a website or listing satisfies neither condition.

**Email** — [Resend Acceptable Use Policy](https://resend.com/legal/acceptable-use). Postmark and Amazon SES have comparable permission-based policies (*verify* when choosing). Gmail and Yahoo bulk-sender rules require SPF, DKIM and DMARC with alignment, one-click unsubscribe (RFC 8058) for marketing mail, and a spam-complaint rate below 0.3 % (secondary sources; confirm against [Google's sender guidelines](https://support.google.com/a/answer/81126)).

**Ghana law** — see [OUTREACH_COMPLIANCE](OUTREACH_COMPLIANCE.md) §1.

## Adding a provider

1. Read its current terms; add a row here with links and dates.
2. Implement the provider interface with an honest `getRetentionRules` and `getPermittedPurposes`.
3. Add a simulated implementation for CI. No test may call the live API unless `LIVE_PROVIDER_TESTS=1` is set and a per-run budget is configured.
4. Add its cost estimate and budget key (COST_CONTROL).
5. Have the owner approve the purpose before enabling the key in production.
